# Operations 四象限可选视图方案

状态：待 review。日期：2026-10-31。本文为产品与实现方案，尚未修改应用功能。

## 目标与入口

在现有「事务 / 科研日志」中的「事务」页加入「列表 / 四象限」切换。首次默认列表，记住当前浏览器上次选择。两种视图使用同一批 Operations 记录和现有类型筛选；切换不创建副本、不丢失筛选。

四象限按照用户对重要性与紧急性的判断组织工作；截止日期继续独立显示，不自动驱动卡片换区。

## 布局

顶部保留新增事务入口和类型筛选，加入视图切换。四象限上方放可折叠的「待分类 · N」收件区，默认有记录时展开；用户可将卡片拖入象限，也可拖回待分类。

| 位置    | 分类         | 行动提示        |
| ------- | ------------ | --------------- |
| 左上 Q1 | 重要且紧急   | 立即处理        |
| 右上 Q2 | 重要不紧急   | 安排计划        |
| 左下 Q3 | 不重要但紧急 | 委派 / 尽快处理 |
| 右下 Q4 | 不重要不紧急 | 减少 / 暂缓     |

桌面为 2×2；窄屏按 Q1→Q2→Q3→Q4 单列排列。每个区域标明名称、符合当前筛选的未完成数量、简短空状态。采用轻量底色和文字标签，不依赖颜色区分象限。截止提醒只强调日期，避免与象限颜色混淆。

矩阵卡片采用紧凑布局，保留标题、类型、状态、已有进度、截止日期，以及专注、编辑入口。说明和项目/论文关联使用现有详情展开方式。列表视图中的已分类卡片增加简短分类标签。

矩阵默认展示未完成事务；下方独立折叠区保留已完成/已归档事务，统一沿用现有关闭状态判断。完成时保留分类，再次开启时回到原象限。列表继续沿用现有的未完成在前、已完成在后的规则。

## 分类与拖拽

1. 历史记录、未指定分类的新事务进入待分类；在某象限的「＋」入口创建时预填该象限。
2. 使用明确拖拽手柄，避免点击编辑、专注、详情或选择文字时误拖。拖动时显示目标区域高亮与占位反馈。
3. 释放后只修改分类；状态、进度、截止日期、类型和关联关系均保持原值。拖回原区、按 Esc 或落在区域外不写入。
4. 提供卡片「移动到」菜单和编辑抽屉中的「四象限分类」选项，包含待分类和四象限。键盘和触屏用户可用相同入口完成分类；正式实现同时支持触屏拖动。
5. 落下即在界面显示目标位置并标记保存中。同一卡片保存期间禁止重复移动；其他卡片仍可操作。成功后显示确认与短时撤销入口；撤销作为一次新的、受版本校验的保存。
6. 保存失败恢复之前位置并显示错误；遇到版本冲突重新加载记录，让用户基于最新内容再次操作，不自动覆盖 Obsidian 或其他窗口的修改。撤销遇到冲突也遵循此规则。
7. Bridge 未连接或明确只读时允许浏览和切换视图，禁用分类写入并说明原因；不引入离线写入队列。

每个象限内首版按现有规则排序：截止日期较早的在前，无截止日期的在后，然后按更新时间倒序；并列时用 id 保持稳定。拖动负责跨区域分类，首版不提供区内手动排序。卡片可能落入目标区域的排序位置，而非鼠标释放处；占位反馈应反映这一规则。

紧急性由用户手动判断。到期、逾期、修改截止日期或启动专注不会自动改分类。Q3 不发送委派消息，Q4 不自动归档、删除或关闭已有提醒。科研日志不参与四象限。

## 数据和现有实现衔接

建议新增单一可选字段，避免两个布尔值出现半分类状态：

```ts
type EisenhowerQuadrant = "do" | "schedule" | "delegate" | "defer";
// RecordItem 新增；空字符串表示用户清除分类，旧记录可省略。
eisenhowerQuadrant?: EisenhowerQuadrant | "";
```

固定映射：do→Q1，schedule→Q2，delegate→Q3，defer→Q4。值只表达分类，不执行相应行动。空字符串与字段缺失都显示为待分类。沿用 Bridge 合并保存语义，用空字符串明确清空字段；不能仅省略字段来清空。

字段随 Operations 记录写入 Obsidian frontmatter，沿用原子写入、历史版本和 contentHash 并发校验。已有笔记无需批量迁移。写入验证类型、枚举和适用集合；读取手工编辑的未知值时，应保持记录可见、显示待分类及异常提示，不能因为此可选字段隐藏整条事务，也不能静默覆盖原值。实现时区分读取兼容与 API 写入校验。

视图偏好用独立版本化 localStorage 键（如 scholarbuddy-operations-view-v1）；存储不可用时使用内存默认值，不影响浏览。偏好随浏览器及站点来源独立保存，分类则随同一 vault 记录共享。

| ----------------------------------------------- | --------------------------------------------------------------------------- |
| app/components/modules/OperationsModule.tsx     | 视图切换、分组、筛选与完成区；抽取共享 OperationCard；新增矩阵及拖拽协调    |

## 实施顺序与验收

1. 数据字段及保存往返：旧记录兼容、显式清空、非法写入拒绝、未知存储值仍可见。
2. 共享卡片和可选矩阵：列表行为保持，分类菜单/编辑器先形成完整可用路径。
3. 拖拽、即时反馈、撤销、失败回退、响应式和中英双语。
4. 关键行为验证及仓库要求的 lint、typecheck、测试和构建。

验收重点：

- 首次仍为列表，切换后刷新恢复视图；两种视图记录一致，类型筛选和数量一致。
- 旧卡片在待分类可见；跨象限、回待分类、刷新、重新读取 vault 后分类一致。
- 分类移动只改分类，原有专注计时与 Profile 归属、截止提醒、编辑和详情正常。
- 空象限、无记录、长标题、大量卡片、不同类型和历史关闭状态均可用。
- 保存失败回退；连续操作与其他窗口/Obsidian 修改不会造成过期覆盖；撤销使用最新有效版本。
- 键盘、触屏、窄屏、滚动中的拖放可完成；非拖动入口可实现完全相同的分类结果。

## 本次 review 建议确认

推荐首版组合为：可选且记忆的矩阵视图、独立待分类区、手动分类、区内按截止日期排序、完成记录折叠、分类持久化到 vault。

优先 review 三个产品选择：是否采用独立待分类区；是否保持纯手动分类；首版是否接受区内自动排序。全部建议按以上默认方案推进，区内自由排序、自动紧急性建议、批量分类和真实委派可作为后续独立需求。
